# Pet Yaya 软件架构

> 状态：第一版软件骨架  
> 更新日期：2026-07-29

## 1. 架构目标

当前阶段不依赖实体机器人，先在电脑上完整验证以下主链路：

```text
主人输入
  → 对话理解
  → 安全检查
  → 生成回复与有限行为
  → 模拟表情/动作输出
  → 提出记忆请求
  → 主人确认
  → 写入长期记忆
  → 更新成长状态
```

软件设计必须满足：

- 对话模型、语音服务和硬件可以独立替换；
- 业务规则能够脱离网络和硬件进行测试；
- AI 不能绕过动作白名单与安全策略；
- 长期记忆必须经过明确确认；
- 未来接入麦克风、摄像头和电机时不修改核心业务；
- 默认只依赖 Python 标准库，先降低开发环境成本。

## 2. 分层结构

```text
┌─────────────────────────────────────────────┐
│ Interfaces                                  │
│ CLI、未来的语音入口、家长端、HTTP/WebSocket │
├─────────────────────────────────────────────┤
│ Application                                 │
│ 会话编排、记忆确认、成长更新、用例流程       │
├─────────────────────────────────────────────┤
│ Domain                                      │
│ 消息、动作、情绪、记忆、成长状态与业务规则   │
├─────────────────────────────────────────────┤
│ Ports                                       │
│ 对话引擎、记忆库、执行器、安全策略的抽象接口 │
├─────────────────────────────────────────────┤
│ Adapters / Infrastructure                   │
│ 模拟器、JSON/SQLite、云端模型、ESP32、屏幕   │
└─────────────────────────────────────────────┘
```

依赖方向只能指向核心层。核心业务不知道设备型号，也不知道未来使用哪个云端模型。

## 3. 模块职责

### `domain`

保存稳定的业务概念：

- `Emotion`：Yaya 可表达的有限情绪状态；
- `ActionCommand`：经过定义的动作，而不是任意电机参数；
- `DialogueResult`：对话引擎提出的回复方案；
- `MemoryCandidate`：等待主人确认的记忆；
- `GrowthState`：互动次数、成长值和已解锁技能；
- `InteractionResult`：一次完整交互的输出。
- `RobotEvent`：统一的输入、回复、设备和故障事件；
- `SessionState`：任意时刻唯一的会话状态；
- `VirtualDeviceState`：静音、网络和虚拟电量。

这一层不能导入网络 SDK、数据库 SDK 或 GPIO 库。

### `ports`

定义外部能力的协议：

- `DialogueEngine`：把文本和有限上下文转为回复方案；
- `MemoryRepository`：保存、读取、删除已确认的记忆；
- `PendingMemoryRepository`：管理等待确认的记忆；
- `GrowthRepository`：保存成长状态；
- `SafetyPolicy`：批准、降级或拒绝动作；
- `Actuator`：输出说话、表情和动作。

### `application`

`PetYayaOrchestrator` 是第一版应用入口，负责：

1. 读取已确认记忆与成长状态；
2. 调用对话引擎；
3. 将模型提出的动作交给安全策略；
4. 调用执行器输出；
5. 保存待确认记忆；
6. 更新可解释的成长数据；
7. 返回适合界面显示的结构化结果。

`SessionManager` 负责确定性状态转换、虚拟设备状态和最近事件历史。事件历史
只保存在内存中，并且不写入原始对话文本。

### `adapters`

当前包含：

- `RuleBasedDialogueEngine`：不联网的规则对话模拟器；
- `OpenAIResponsesDialogueEngine`：严格结构化的Responses API适配器；
- `ResilientDialogueEngine`：网络、配置或服务异常时自动降级；
- `ConservativeSafetyPolicy`：动作白名单；
- `VirtualDeviceSafetyPolicy`：低电时阻止运动动作；
- `ConsoleActuator`：在终端打印表情和动作。

后续可替换为：

- 实时语音或大语言模型适配器；
- STT/TTS 适配器；
- ROS 2 或串口硬件执行器；
- 摄像头视觉适配器。

### `infrastructure`

当前提供两组仓储：

- 内存仓储，用于快速、隔离的自动测试；
- SQLite 仓储，用于保存已确认记忆、待确认记忆、成长值和已解锁技能。

SQLite 数据库默认位于 `software/data/pet_yaya.db`。该目录不会提交到版本库，
避免把真实使用者的个人记忆混入源代码。

## 4. 安全边界

对话引擎只能选择预定义动作：

```text
idle
nod
tilt_head
look_left_right
happy_wiggle
sleep_pose
```

以下原则由确定性代码执行：

- 未知动作一律降级为 `idle`；
- 对话引擎不能输出轮速、PWM 或舵机角度；
- 未来的运动适配器还要检查障碍物、电量、急停和通信状态；
- 安全策略失效时默认不执行动作；
- 回复内容和动作控制使用不同通道。
- 虚拟电量不高于20%时，运动动作降级为 `idle`。

## 5. 记忆规则

长期记忆采用两步写入：

1. 对话引擎只能生成 `MemoryCandidate`；
2. 主人明确批准后，应用层才将其写入 `MemoryRepository`。

记忆至少包含：

- 唯一标识；
- 分类；
- 内容；
- 创建时间；
- 来源；
- 是否经过确认。

未确认内容不能出现在后续长期上下文中。

## 6. 成长规则

第一版采用可解释的数值规则，不让语言模型自行修改人格：

- 每完成一次正常互动，互动次数加一；
- 每次互动增加少量成长值；
- 达到明确阈值后解锁技能；
- 阈值和奖励规则在代码中固定；
- 成长状态可以查看和重置。

后续可以增加好奇心、活力和安静程度等性格维度，但每次变化必须限幅，并保存变化原因。

## 7. 会话状态与事件

会话状态包括：

```text
idle
listening
thinking
speaking
awaiting_confirmation
muted
offline
error
```

系统通过统一事件驱动状态转换，包括用户输入、开始思考、回复开始与结束、
记忆确认或拒绝、打断、静音、网络、电量、触摸、碰撞、错误和关闭。

- 静音状态拒绝普通输入，但不阻止管理命令；
- 离线状态继续使用本地规则引擎；
- 等待记忆确认时，新的普通输入会被拦截；
- 碰撞和打断事件使当前会话返回安全基线状态；
- 运行异常进入 `error`，状态和数据库仍可检查；
- 最近200个事件保存在内存中，默认不持久化。

## 8. 语言模型适配

默认运行模式为 `auto`：

```text
有API密钥且在线
  → Responses API
  → JSON Schema结构化结果
  → 本地字段验证
  → 动作安全策略

无密钥、离线、超时、拒绝或格式错误
  → 本地规则引擎
```

模型输出包含回复、表情、白名单动作和可选记忆候选。模型不能直接写入长期记忆，
也不能生成底层硬件参数。请求设置 `store: false`，只发送当前输入、最多20条
已确认记忆摘要和成长状态，以及最近4轮已完成且不含待确认记忆的问答。
短期问答仅保存在编排器内存，单轮上限为800字用户输入和400字回复；失败的
交互不加入历史。清空历史、成功删除长期记忆、重置及退出时清理相应历史。
它不等同于已确认事实，也不会自动成为长期记忆。本地和云端适配器共用上下文构造。

默认模型为 `gpt-5.6`，可以通过环境变量替换。API密钥只从
`OPENAI_API_KEY` 读取，不保存到项目文件或SQLite。

## 10. 运行方式

在 PowerShell 中：

```powershell
cd path\to\Pet_yaya\software
.\run_simulator.cmd
```

模拟器支持：

- 输入普通文本与 Yaya 对话；
- 输入“我喜欢……”或“记住……”生成待确认记忆；
- 输入 `/yes` 批准最近一条待确认记忆；
- 输入 `/no` 拒绝最近一条待确认记忆；
- 输入 `/memory` 或 `/memories` 查看带编号的长期记忆；
- 输入 `/forget 编号` 删除指定记忆；
- 输入 `/growth` 查看成长状态；
- 输入 `/model` 查看模型、当前引擎和降级原因；
- 输入 `/status` 查看会话、静音、网络和电量；
- 输入 `/mute` 或 `/unmute` 模拟麦克风状态；
- 输入 `/offline` 或 `/online` 模拟网络变化；
- 输入 `/battery 电量` 模拟电量和低电保护；
- 输入 `/touch` 或 `/collision` 模拟设备事件；
- 输入 `/interrupt` 发出打断事件；
- 输入 `/events` 查看最近事件；
- 输入 `/reset yes` 清除全部记忆和成长状态；
- 输入 `/quit` 退出。

运行测试：

```powershell
cd path\to\Pet_yaya\software
python -m unittest discover -s tests -v
```

## 11. 电脑语音适配（2026-09-09）

新增 `adapters/voice.py`，通过 CLI 的 `/listen` 显式录音，最长15秒。
识别文字默认直接进入原有 orchestrator；`/review on` 可恢复手动确认，业务核心不依赖音频包。
Windows sounddevice 负责录音，CPU faster-whisper medium（存在时）负责普通识别，
small 负责简短确认，SAPI 负责中文朗读。朗读使用短生命周期子进程。
识别由 speech_worker_client 管理单请求常驻子进程，通过逐行 JSON 管道交互，
worker 按需加载最多两个模型并复用。取消/超时/错误会杀进程并丢弃整条结果，
下次请求重启；正常完成则保留模型。CLI 在 finally 中关闭后台，另注册进程退出清理。
后台常驻的是模型，不是麦克风；没有持续监听。
2026-09-10：cuBLAS/cuDNN已通过NVIDIA wheels装到项目环境，worker在导入识别库前配置环境内DLL目录。
语音启动入口默认auto（GPU优先），客户端在GPU异常时销毁进程并用CPU重试一次，后续保持CPU。
显式cuda用于严格诊断，显式cpu可关闭GPU；取消绝不作为GPU故障自动重试。
实测GPU热识别约0.3–0.4秒，两个ASR模型与Qwen共存成功，详见README基准记录。
原始录音只在项目 data/voice-temp 下临时存在，正常退出或取消后清理。
强制杀进程或断电可能残留临时文件，量产前需增加安全的过期清理机制。

模型回复仍先由现有编排器完成校验、历史/成长更新和控制台输出，随后 CLI 朗读全文。
因此朗读取消不回滚已完成对话；生成取消仍不提交未完成内容。
录音、识别和朗读目前是 CLI 外围阶段，尚未扩展业务 SessionState；不能用核心 idle
状态推断麦克风是否正在录音。CLI 同步互斥保证播放时不能开始新录音，控制台明确提示阶段。
静音和待确认记忆会在普通 `/listen` 打开麦克风前拦截。语音识别结果不执行 slash 管理命令。
2026-09-10：语音轮次的记忆询问成功朗读后，CLI 自动调用一次5秒确认录音。
`domain/voice_confirmation.py` 对整句明确同意/拒绝短语进行确定性匹配，确认输入不进入模型。
没有明确同意或录音失败、取消时拒绝并清理候选；询问朗读失败/中断时不录音，保留手动确认。
确认不增加成长值，已保存记忆不因结果提示朗读失败而回滚。只在语音发起且朗读开启时自动确认。

自然语言记忆升级：domain/memory_intent 定义意图，adapters/memory_intent 使用本地Qwen
流式结构化输出 request/approve/reject/revise/uncertain，不直接执行数据库操作。
常用表达由规则处理，复杂请求仅在含记忆相关线索时额外分类；指代从最近4轮用户原文提取，
来源匹配和敏感信息检查由程序执行。分类不确定时不允许另一轮模型建议绕过该检查。
确认仅绑定当前有效候选；更正原地更新候选内容，但不写长期记忆，必须再次确认。
语音最多两轮确认录音，第二轮仍不明确或继续更正则放弃候选；键盘也支持自然确认。
取消传播到语义请求，服务故障不授权保存。本轮没有启用直接记忆模式。
自动测试覆盖边界和子进程取消；`check_voice.py` 用合成音频测试，无需录制用户环境。

## 12. 下一阶段

2026-09-11 已接入自动结束录音：LiveSpeechDetector 复用捆绑Silero v6的ONNX session，
每次录音独立初始化h/c和64采样上下文，16kHz下每512采样推理一次。SpeechEndpoint负责
确定性停止规则：96ms人声起始、普通静音2.5秒/确认0.8秒、无声等待5秒、总时限15/5秒。
根据实际句中截断反馈，普通等待从1.2秒放宽到2.5秒，支持 /pause N 在1到5秒内调整。
音频回调使用有界队列，主循环推理和检测按键，避免在实时回调中运行模型。
语音检测失败或队列溢出不提交录音；/endpoint off为手动退路。不做声纹识别或自动唤醒。
自动测试包含策略边界、模拟录音资源释放；check_speech_endpoint.py用合成音频验证真实模型。

1. 人工验收按键语音：麦克风、中文准确度、默认音频输出和取消恢复；
2. 增加会话超时和摘要；
3. 优化分句朗读和语音状态事件，评估唤醒词前先完善隐私指示；
4. 增加家长管理API；
5. 为真实模型、语音和故障路径继续补充测试。
